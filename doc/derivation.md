# 麦克纳姆轮运动学推导

这份文档解释 `mecanum_kinematics.cpp` 里那八个正负号是怎么来的。
答辩时被问「你这个公式哪来的」, 能顺着推一遍就够了。

---

## 1. 为什么麦轮能横移

普通轮子只能沿前进方向滚动, 侧向是死的。麦轮的轮缘上斜装着 16 个可自由转动的辊子,
辊子轴线与轮轴成 45 度。

这个 45 度是关键: 它把「轮子的转动」和「地面的横向移动」耦合起来了。
当四个轮子以特定组合转动时, 横向的推力互相抵消或叠加, 车就横着走了。

辊子的存在意味着一个方向是自由的（沿辊子轴滑动, 无摩擦）,
另一个方向是锁死的（垂直于辊子轴, 必须靠轮子转动来匹配）。
**运动学推导的本质, 就是把这个「锁死的方向」写成一个等式。**

## 2. 坐标与符号约定

```
        x (车头方向)
        ↑
        │
  LF ●  │  ● RF        LF = left_front, RF = right_front
        │             LB = left_back,  RB = right_back
────────┼────────→ y (车身左侧)
        │
  LB ●  │  ● RB
```

- `vx` 前进速度, 正 = 向车头
- `vy` 横移速度, 正 = 向**车身左侧**（ROS 约定 y 轴朝左, 不是朝右）
- `wz` 自转角速度, 正 = **逆时针**（从上往下看, 右手定则绕 +z）
- 轮子正转 = 车往前（已由仿真实测确认, 见第 6 节）

四个轮子在车体系下的位置, 取自 `chassis.urdf.xacro`:

| 轮子 | lx | ly | reflect |
|------|----|----|---------|
| LF | +0.2 | +0.2 | +1 |
| RF | +0.2 | −0.2 | −1 |
| LB | −0.2 | +0.2 | −1 |
| RB | −0.2 | −0.2 | +1 |

`reflect` 是 URDF 里区分左右手性轮毂的参数。**注意 LF 和 RB 同号、RF 和 LB 同号**,
这就是标准的「X 型」布局。如果装成「O 型」(LF/RB 反号), 下面的公式全都要改。

`lx = wheel_base / 2 = 0.2`（前后半距）
`ly = wheel_track / 2 = 0.2`（左右半距）
`K = lx + ly = 0.4`（车心到某个轮子的曼哈顿距离）

## 3. 单个轮子的无滑移约束

### 3.1 轮子接地点处的车体速度

车体以 `(vx, vy, wz)` 运动。刚体上任意一点的速度是「平动 + 转动」:

```
v_point = (vx − wz · ly,  vy + wz · lx)
```

转动项的符号值得单独看一眼: 绕 +z 逆时针转, 位于 +y 侧（左侧）的点会向 −x（后退）方向走,
所以 x 分量是 `−wz·ly`; 位于 +x 侧（前方）的点会向 +y（左侧）走, 所以 y 分量是 `+wz·lx`。

### 3.2 辊子轴的方向

轮轴沿 y 方向（URDF 里 `<axis xyz="0 1 0"/>`）。辊子与轮轴成 45 度,
所以辊子轴在水平面的投影 `u` 与 x 轴成 45 度, 方向取决于 `reflect`:

- `reflect = +1`: `u = (cos45°, +sin45°)`, 即指向「前方偏左」
- `reflect = −1`: `u = (cos45°, −sin45°)`, 即指向「前方偏右」

垂直于辊子轴的方向记作 `n`（把 `u` 逆时针转 90 度）:

- `reflect = +1`: `n = (−sin45°, +cos45°) = (−0.707, +0.707)`
- `reflect = −1`: `n = (+sin45°, +cos45°) = (+0.707, +0.707)`

### 3.3 约束等式

辊子只能沿自己的轴滚动, **不能侧滑**。所以接地点速度在 `n` 方向的分量,
必须等于轮子转动提供的圆周速度在 `n` 方向的分量:

```
v_point · n  =  (w · R) · (x̂ · n)
```

轮子圆周速度方向是 `x̂`（因为轮轴是 y）, 所以 `x̂ · n` 就是 `n` 的 x 分量。

## 4. 四个轮子逐个推

### LF (lx=+0.2, ly=+0.2, reflect=+1)

```
v_point = (vx − 0.2·wz,  vy + 0.2·wz)
n       = (−0.707, +0.707)
x̂ · n   = −0.707
```

```
−0.707(vx − 0.2wz) + 0.707(vy + 0.2wz) = −0.707 · wR
```

两边除以 0.707:

```
−(vx − 0.2wz) + (vy + 0.2wz) = −wR
−vx + 0.2wz + vy + 0.2wz     = −wR
wR = vx − vy − 0.4·wz
```

**w_LF = (vx − vy − 0.4·wz) / R** ✓

### RF (lx=+0.2, ly=−0.2, reflect=−1)

```
v_point = (vx + 0.2·wz,  vy + 0.2·wz)
n       = (+0.707, +0.707)
x̂ · n   = +0.707
```

```
0.707(vx + 0.2wz) + 0.707(vy + 0.2wz) = 0.707 · wR
wR = vx + vy + 0.4·wz
```

**w_RF = (vx + vy + 0.4·wz) / R** ✓

### LB (lx=−0.2, ly=+0.2, reflect=−1)

```
v_point = (vx − 0.2·wz,  vy − 0.2·wz)
n       = (+0.707, +0.707)
```

```
0.707(vx − 0.2wz) + 0.707(vy − 0.2wz) = 0.707 · wR
wR = vx + vy − 0.4·wz
```

**w_LB = (vx + vy − 0.4·wz) / R** ✓

### RB (lx=−0.2, ly=−0.2, reflect=+1)

```
v_point = (vx + 0.2·wz,  vy − 0.2·wz)
n       = (−0.707, +0.707)
x̂ · n   = −0.707
```

```
−0.707(vx + 0.2wz) + 0.707(vy − 0.2wz) = −0.707 · wR
wR = vx − vy + 0.4·wz
```

**w_RB = (vx − vy + 0.4·wz) / R** ✓

## 5. 结果

写成矩阵形式（这是代码里那四行）：

```
⎡ w_LF ⎤   ⎡ 1  −1  −K ⎤ ⎡ vx ⎤
⎢ w_RF ⎥   ⎢ 1  +1  +K ⎥ ⎢ vy ⎥
⎢ w_LB ⎥ = ⎢ 1  +1  −K ⎥ ⎢    ⎥ / R
⎣ w_RB ⎦   ⎣ 1  −1  +K ⎦ ⎣ wz ⎦
```

这个 4×3 矩阵记不住也没关系, 记住它的**结构**就行:

- **第一列全 +1**: 前进时四个轮子必须同速同向, 这是最直观的约束
- **第二列 −,+ ,+, −**: 横移时对角同号。因为 LF/RB 手性相同、RF/LB 手性相同
- **第三列 −,+,−,+**: 自转时左右两组反向, 形成力偶

### 正运动学

上面那个矩阵 `A` 的四个行向量**两两正交**（可以验算: 任意两行点积都是 0）。
这个性质让反解变得极简 —— 最小二乘解 `(AᵀA)⁻¹Aᵀ` 里的 `AᵀA` 是个对角阵, 于是反解就是
「按列求和再除以 4」:

```
vx = R · ( w_LF + w_RF + w_LB + w_RB) / 4
vy = R · (−w_LF + w_RF + w_LB − w_RB) / 4
wz = R · (−w_LF + w_RF − w_LB + w_RB) / (4K)
```

这就是 `ForwardKinematics()`。里程计用它把实测轮速还原成底盘速度。

## 6. 为什么相信这组符号是对的

推导只是纸面功夫, 真正的问题是「仿真里的轮子正转到底是前进还是后退」。
这一点靠 `chassis.urdf.xacro` 里的 transmission 参数是**看不出来**的:

```xml
<mechanicalReduction>19.2032</mechanicalReduction>   <!-- 左轮正 -->
<mechanicalReduction>-19.2032</mechanicalReduction>  <!-- 右轮负 -->
```

右轮是负的, 看起来应该翻符号。但实测结果不是。

**做法**: 直接旁听示例控制器运行时的 `/joint_states`, 把四个轮子的角速度符号
和它的 `cmd_[6][4]` 力矩表逐帧对照。示例控制器的表是:

```cpp
{ tau,  tau,  tau,  tau},   // state 0: forward
{-2tau, -2tau, -2tau, -2tau},  // state 1: backward
{-tau,  tau,  tau, -tau},   // state 2: left
{2tau, -2tau, -2tau, 2tau},   // state 3: right
{2tau, -2tau, 2tau, -2tau},   // state 4: clockwise
{-tau,  tau, -tau,  tau}    // state 5: counterclockwise
```

实测（15 秒、750 帧, 每 2 秒换一档）:

| 时刻 | w_LF | w_RF | w_LB | w_RB | 与哪个 state 的符号一致 |
|------|------|------|------|------|------------------------|
| 0.0s | +3.78 | −12.65 | −12.43 | +3.50 | state 3 (right) `+ − − +` |
| 2.0s | +21.00 | −15.58 | +21.77 | −16.87 | state 4 (clockwise) `+ − + −` |
| 4.0s | −6.43 | +4.35 | −6.02 | +3.87 | state 5 (ccw) `− + − +` |
| 6.0s | +5.87 | +6.53 | +5.43 | +7.05 | state 0 (forward) 全正 |
| 8.0s | −15.80 | −15.47 | −15.80 | −16.81 | state 1 (backward) 全负 |

**五档符号全部逐一吻合**, 说明:

1. `setCommand()` 的数值符号直接就是轮子实际转动方向的符号,
   transmission 里的负 `mechanicalReduction` 不影响 joint 侧的命令
2. 轮子正转 = 车前进（state 0 四轮全正, 车确实往前走了）

这一步省掉了后面反复试符号的时间。如果没有实测, 很可能会在代码里多加一层
「右轮取反」, 然后怎么也调不对。

## 7. 数值验证

`test/test_kinematics.cpp` 里的断言, 以及一份独立的宿主机验证结果:

```
K = 0.400000  (expect 0.4)                                  ✓
纯前进 vx=0.2 -> LF 2.6230 RF 2.6230 LB 2.6230 RB 2.6230    ✓ 四轮同速
纯左移 vy=0.2 -> LF -2.6230 RF 2.6230 LB 2.6230 RB -2.6230  ✓ 对角同号
逆时针 wz=0.5 -> LF -2.6230 RF 2.6230 LB -2.6230 RB 2.6230  ✓ 左退右进
正逆互逆（穷举 20×20×30 网格）最大还原误差 = 1.332e-15      ✓
1 m/s -> 13.115 rad/s = 125.2 rpm                           ✓
```

`1.332e-15` 是双精度浮点的极限量级, 说明正逆解在数值上严格互逆。

顺带一个 sanity check: `urdf` 里 `max_velocity = 50 rad/s`,
换算成线速度是 `50 × 0.07625 = 3.8 m/s`。这就是这台车的理论极速,
PID 再给力也超不过去, 所以 `max_linear_velocity` 设成 2.0 是合理的。
